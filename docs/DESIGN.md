# Hubmorrow design system

Hubmorrow helps community coordinators decide where limited battery packs should go. The first screen names that job and shows its result. Users edit needs, choose available power, then test the allocation in tougher conditions.

## Direction

Calm, practical and readable. The Apple design analysis informed restrained surfaces, clear type and generous spacing. These are adapted principles, not copied assets. The original H mark joins two hub pillars around a shared center.

## Content

Use short, direct English. Explain controls before algorithms. Put technical details in How it works. Label sample inputs honestly. A calculated score is not a count of real people helped.

## Interaction

Editing inputs marks results as previous and disables exports until recalculation. Keyboard focus, native labeled controls, 44 px primary touch targets and reduced motion are retained. Mobile shows results first with a direct link to plan settings. Navigation keeps text on mobile. Earlier plan imports and browser-storage keys remain compatible.

## Review

The original interface had tiny labels, prominent prototype language and algorithm jargon in its main flow. Version 1.1 raises the type scale, simplifies instructions and creates a consistent identity.

12ui was installed and its pricing-only dry run inspected. Hosted generation requires a new GitHub OAuth approval for private profile and email access, so no paid generation or unapproved access occurred. Anatomy was not found in the available skill catalog. Remote Desktop Commander reported its device offline. Hype Design Production is for fixed event-certificate PDFs and did not apply to this interface.
